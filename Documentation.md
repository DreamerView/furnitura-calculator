PLS: при включённой опции применяется согласованное временное правило — одна пластина на каждый соединяемый элемент обвязки створки (привод, ножницы, удлинитель, угловая передача, шпингалет). Пластины из исходного состава заменяются вычисленным количеством без накопления; количество створок учитывается один раз. Рамные зацепы, петли, накладки, ручки и инструменты не участвуют. Поле plateUnits карточки артикула позволяет задать исключение 0 или другой целый коэффициент. Это правило пользователя, а не подтверждённая карта монтажных стыков.

В новых накладных сохраняется происхождение количества пластин. Удаление/изменение количества связанной строки предлагает пересчёт; отказ сохраняет ручную поправку. Ручное изменение PLS также сохраняется отдельно. Старые накладные без этих связей не изменяются. Общая система зависимостей ответных планок и накладок этим обновлением не реализуется.

# Documentation — FUTURUSS 2026.09.28.4

## 1. Архитектура интерфейса

FUTURUSS использует Vue SPA-документ `index.php` для калькулятора и управления. HTML-конструктор `configurator.html` открывается отдельной страницей в именованной вкладке браузера; Vue-страница `#/advertising` управляет рекламным изображением.

Маршруты:

| Маршрут | Назначение | Доступ |
|---|---|---|
| `#/calculator` | публичный калькулятор | всем после первичного setup |
| `#/login` | логин/пароль или активация Client по секретному ключу | всем |
| `#/setup` | первый Central | только пока setup не завершён |
| `#/users` | управление веткой | Central, Dealer, Subdealer |
| `#/advertising` | управление рекламным изображением в Vue | только Central |
| `#/configurator` | совместимый старый адрес, перенаправляет на `#/advertising`; HTML-конструктор открывается отдельной вкладкой | только Central |
| `#/next` | compatibility redirect → `#/users`; UI-кнопка «Следующее · Скоро» неактивна | Central, Dealer, Subdealer |

Client при попытке открыть `#/users` возвращается в калькулятор. Публичный пользователь перенаправляется внутри SPA на `#/login`. Документ при этом не перезагружается.

`access.php`, `login.php`, `setup.php` — только compatibility aliases для старых закладок; активная навигация на них не ссылается.

## 1.1 Верхняя панель калькулятора

Калькулятор не показывает административную навигацию рядом с вкладкой `Накладная`. Session actions находятся в правой header-группе рядом с `Настройки` и `Каталог`:

- Central / Dealer / Subdealer: `Вернуться в управление` + `Выйти`;
- Client: `Выйти`;
- public: `Войти`.

Кнопка `Вернуться в управление` ведёт на `#/users`. Отдельные role badge (`Central`, `Dealer`, `Subdealer`) и кнопка `Пользователи` в calculator header не используются. Вход через встроенную модалку не перебрасывает пользователя в управление и сохраняет route `#/calculator`.

## 2. Первый запуск

До создания первого администратора API `auth_status` возвращает `setupRequired=true`. Router guard оставляет доступным только `#/setup`.

После успешного `setup_admin` создаётся Central и SPA сразу переходит в `#/users` без полной перезагрузки документа.

## 3. Preloader и отсутствие FOUC

`index.php` начинает работу с:

- `class="app-booting"`;
- `data-interface-theme="default"`;
- полноэкранным `#appPreloader`.

Калькулятор и SPA views скрыты, пока bootstrap не загрузит локальные зависимости, legacy calculator modules, SPA и начальный route. После двух animation frames preloader плавно скрывается.

Тема берётся из серверного `settings.theme` за preloader. Доступны `default`, `soft`, `easy`, `glossy`, `material`; `default` соответствует текущему рабочему дизайну. Старое browser preference темы не используется, поэтому промежуточные оформления не показываются.

## 4. Каталог и настройка калькулятора

Каталог соответствует контракту `futuruss-matrix` v2: `articles` и `kits`. HTML-конструктор находится в `configurator.html` и открывается из калькулятора или управления отдельной повторно используемой вкладкой браузера. Рекламные настройки доступны в Vue по маршруту `#/advertising`.

Central редактирует комплектации, диапазоны размеров, составы ячеек и артикулы в отдельной вкладке HTML-конструктора. Рекламное изображение управляется Vue-страницей `#/advertising`. Изменения каталога сохраняются защищённым `catalog_save` в `storage/state.json`. Фото товаров из конструктора и базы артикулов калькулятора добавляются или удаляются отдельным защищённым API `catalog_photo_mutate`; браузерный кэш не является источником фотографий. Сервер проверяет роль Central, CSRF и содержимое изображения.

На чистой установке API редактора получает исходный каталог из закрытого `storage/default-catalog.json`; сам HTML не содержит копию номенклатуры. Если серверный каталог ещё не создан, редактор однократно проверяет прежнюю библиотеку `localStorage`, затем сохраняет выбранный каталог через API. После этого сервер остаётся единственным источником каталога.

Если серверный каталог ещё не создан, калькулятор показывает «Данные ещё не загружены» и блокирует расчётные поля. Редактор доступен только Central и повторно проверяется серверным API.

## 5. Цены

Калькулятор публичный, но цены закрыты сервером. API перед отдачей каталога обнуляет `article.price`, если текущему actor нельзя видеть цену.

Право:

`effective_price_access = price_access(self) AND price_access(parent) AND ...`

Для публичного пользователя `canViewPrices=false`.

## 6. Иерархия

### Central

Создаёт только корневой Dealer. `parent_id` из client request игнорируется.

### Dealer / Subdealer

Оба используют серверную роль `dealer`. Они могут создать только:

- `dealer` → отображается как Subdealer;
- `client` → Client.

Родителем сервер автоматически ставит `nodeId` текущего actor.

### Client

Client не создаёт пользователей, не изменяет иерархию и **не имеет management hierarchy**. API `hierarchy` разрешён только ролям `central` и `dealer`.

## 7. Управление пользователями

Экран `#/users` содержит верхнее меню:

- **Пользователи** — рабочий RouterLink с точным active-state;
- **Следующее · Скоро** — неактивный placeholder без перехода и active-state.

Создание — через modal. Редактирование использует ту же modal с заполненными данными. `More` содержит:

- `Редактировать`;
- `Удалить`.

Удаление всегда подтверждается отдельной modal. Dealer/Subdealer удаляется каскадно вместе с его дочерней веткой.

Критичные динамические подписи кнопок выводятся через Vue binding (`v-text`), а не одиночные `{...}`. Это предотвращает отображение строк вроде `{createButtonText}`, `{submitButtonText}` или `{deleting?...}` пользователю.

## 8. Privacy

Central видит Client только redacted. Из ответа убираются:

- `contact_name`;
- `phone`;
- `email`;
- `public_info`;
- `secret_hint`.

## 9. Авторизация

- Central/Dealer/Subdealer: логин + пароль;
- Client получает секретный ключ только для первичной активации; ключ сам по себе не создаёт сессию;
- при активации Client обязан создать глобально уникальный логин и пароль;
- после активации Client входит по логину и паролю;
- пароль хранится через `password_hash`, secret key — только как hash;
- меняющие API запросы защищены CSRF;
- Enter работает как submit; парольные поля имеют локальный show/hide.

Вход/выход обновляет reactive session state и маршрут без `location.reload()`.

## 10. Локальные зависимости

Vue, router layer, IndexedDB adapter, icon kit, i18n и application JS находятся внутри архива. Единственное разрешённое сетевое исключение — SheetJS CDN для Excel; он догружается после `window.load` и не блокирует первый рендер.

Каталог хранится на сервере и не записывается в `localStorage`. При первом открытии HTML-конструктор может перенести прежнюю локальную библиотеку только если серверный каталог отсутствует; после успешного сохранения сервер становится единственным источником истины.

## 11. UI Icon Kit

Системные action-иконки находятся в `assets/icons/*.svg` и подключаются `assets/css/icons.css`. Используются outline-контуры, наследующие `currentColor`. Внешние icon fonts запрещены; SheetJS CDN разрешён только как ленивое исключение для Excel.

### Ленивый SheetJS

## 16. Локализация 2026.09.23.9

Поддерживаются `ru`, `en`, `tr`: Русский, English, Türkçe. `assets/js/i18n.js` переводит SPA и legacy DOM без reload и наблюдает динамически добавляемые элементы. Выбор хранится в IndexedDB (`futuruss.language`).

## 17. Глобальные темы

Central видит кнопку `Дизайн` на `#/users` и может выбрать `Default`, `Soft`, `Easy`, `Glossy`, `Material`. Значение хранится в `state.json → settings.theme`. Public endpoint `app_settings` нужен только для чтения темы до показа интерфейса; `app_settings_update` разрешён только Central и защищён CSRF.

## 18. Client activation policy

Секретный ключ не создаёт сессию. `login_key` оставлен как compatibility check и возвращает `requiresRegistration=true`. Рабочий поток — `client_register`: key + уникальный login + password. После регистрации создаётся user role `client`, node получает `registered=true`, и только тогда возможен обычный password login. Право цены всё равно вычисляется по родительской цепочке. Перевыпуск ключа удаляет старый Client user и сбрасывает регистрацию.

## 19. Глобальная уникальность логина

`AccessService::loginAvailable()` выполняет case-insensitive проверку по всей таблице users. Endpoint `login_available` используется формами создания/редактирования Dealer/Subdealer, setup Central и Client activation. При edit текущий account исключается из проверки. Финальный create/update/register всегда повторяет проверку сервером.


## 20. I18n и темы — 2026.09.23.10

Language selector использует фиксированные native labels `Русский / English / Türkçe` и помечен `data-i18n-ignore`, поэтому переводчик не пытается переводить названия самих языков. `FuturussI18n.t()` проверяет структуру словаря и при любой отсутствующей/некорректной записи возвращает исходный текст вместо `undefined`. Все экземпляры переключателя синхронизируются событием `futuruss:language`.

`Default` остаётся эталонным текущим интерфейсом и не перерабатывается. Альтернативные темы являются отдельными визуальными системами:

- `Soft` — Apple-like: спокойный серый фон, белые поверхности, большие радиусы, мягкие тени, системный синий акцент.
- `Easy` — повышенная читаемость: крупнее поля и кнопки, плоские поверхности, усиленные границы и высокий контраст.
- `Glossy` — стеклянные полупрозрачные поверхности, blur, градиенты, отражения и плавающие слои.
- `Material` — Material 3: tonal surfaces, фиолетовый primary, pill controls, filled/outlined поля и elevation.

## 21. Полностью реактивная интернационализация — 2026.09.23.12

Поддерживаются `ru`, `en`, `tr`: Русский, English, Türkçe. Переключение не выполняет reload и не ждёт IndexedDB. `FuturussI18n.state.language` является реактивным Vue-state, а селект языка связан с ним через computed `v-model`.

Переводчик хранит исходный текст каждого DOM text-node и атрибутов `placeholder`, `title`, `aria-label`, `alt`, `content` в WeakMap. Поэтому при переключении EN → TR или TR → RU перевод всегда строится из исходной русской строки, а не из уже переведённого текста. Это устраняет смешанные языки и частичный перевод после нескольких переключений.

MutationObserver переводит динамически добавленные элементы и сообщения. Для legacy-калькулятора сохранён DOM translation bridge; SPA и session controls получают тот же locale state. API errors локализуются перед показом пользователю. Названия языков `Русский / English / Türkçe` являются native labels и намеренно исключены из автоматического перевода.

Автоматический `tests/i18n-reactive.test.js` проверяет реактивную архитектуру и полный EN/TR runtime coverage пользовательских строк.


## 22. Отдельный HTML-конструктор и Vue-настройка рекламы — 2026.09.28.2

Central открывает исходный `configurator.html` из калькулятора или меню управления в именованной вкладке `FUTURUSS_CONFIGURATOR`. Повторный выбор «Настройка калькулятора» повторно использует эту вкладку и возвращает к ней фокус; iframe не используется. Кнопка «Вернуться в управление» ведёт к `index.php#/users`.

HTML-конструктор загружает каталог через `catalog_editor` и сохраняет комплектации и артикулы через `catalog_save` с CSRF. Перед полной записью он перечитывает рекламные поля и фото товаров с сервера, чтобы не затереть данные, изменённые в другом интерфейсе. После сохранения HTML отправляет межвкладочный сигнал; открытые SPA-калькуляторы перечитывают каталог.

Vue-страница `#/advertising` предназначена Central для загрузки и удаления рекламного изображения. Она обновляет только рекламные поля на свежем серверном каталоге, сохраняет их через `catalog_save` и обновляет открытые вкладки калькулятора. Реклама остаётся частью каталога, который API хранит в `storage/state.json`.

Исходная библиотека хранится в закрытом `storage/default-catalog.json`, не зашивается в HTML. При отсутствии серверного каталога возможен однократный перенос старого ключа localStorage; дальнейшие изменения сохраняются через API.

## 23. Централизованные фото товаров — 2026.09.28.3

PHP должен иметь право записи в `storage` и `storage/product-photos`. Изображения артикула FUTURUSS хранятся отдельными файлами в закрытой папке `storage/product-photos`; доступ к ним идёт через публичный API-маршрут `product_photo`. `storage/state.json` содержит ссылки на эти файлы внутри `catalog.articles[article].photos`, без содержимого изображений. Конструктор сжимает изображения и отправляет их через `catalog_photo_mutate`; камера в базе артикулов использует тот же API. API требует активную сессию Central и CSRF, проверяет MIME и размеры изображения и ограничивает карточку пятью фотографиями. Удаление убирает ссылку из общего каталога и файл с сервера. Старые серверные data URI автоматически переносятся в файлы при следующем полном сохранении каталога.

При запуске калькулятор строит список фотографий из ответа `catalog` и не смешивает его с `futuruss-master-overrides`. Фото каталога не загружаются из папки на компьютере пользователя. Перед полной записью каталога HTML-конструктор заново получает актуальные фото с сервера, чтобы сохранить загрузки, сделанные из другого интерфейса.

## 24. Проверка обновления фото — 2026.09.28.4

При загрузке изображения сервер декодирует и валидирует файл, вычисляет SHA-256 его байтов и сохраняет сумму вместе с записью фото. Для совпадающего имени файла он сравнивает SHA-256: одинаковое содержимое считается повтором, изменённое — заменой существующего фото с сохранением его позиции в списке. Замена создаёт файл с новым случайным идентификатором и URL; старый файл удаляется только после успешной записи каталога. Это также обходит immutable-кэш браузера. Максимум пять фото на артикул сохраняется, но замену можно выполнить и при заполненном лимите.

## Соединения и замены — 2026.10.08.6
В отдельном просчёте кнопка-карандаш возле ответной планки открывает выбор артикула. Окончания 35/40/45/50 предлагаются только при наличии соответствующего варианта профиля; отсутствие 40 не создаёт фиктивный артикул. Ручная замена требует подтверждения совместимости.
PLS не равны числу деталей. kit.plateConnections (или переопределение cell.plateConnections) описывает проверенные соединения: id, from/to (артикул либо роли drive/scissors), cut single/double, verified, count (на створку), plates (по умолчанию 1). Редактор в конструкторе позволяет задать пары. Непроверенные или отсутствующие концы не рассчитываются автоматически. Старые one-per-sash-element-v1 просчёты не мигрируют.
Ограничение выпуска: для большинства существующих комплектов ещё требуется заполнение и технологическая проверка карты соединений. Программа об этом предупреждает; количество PLS из рецепта не объявляется подтверждённым. Динамическая смена нижнего узла подтверждена только для стандартной roller11 с одним XUSP/XU.2 и одной ответной деталью, при наличии XPNB.
