# Agents.md

Версия: `2026.10.09.1`.

1. Эталон интерфейса — WorkDesk: grouped-поверхности, синий акцент и системная светлая/тёмная палитра. Сохранять DOM, бизнес-логику, обработчики и пути калькулятора.
2. На чистой установке первым обязателен setup Central. После setup калькулятор публичный.
3. Реальные цены нельзя отдавать public-клиенту через скрытый JSON/API. Доступ только при эффективном разрешении ветки.
4. Источник каталога — серверное хранилище. Исходный каталог хранить только в закрытом storage; отдавать его только авторизованному Central через API настройки.
5. IndexedDB использовать для локальных UI-настроек/черновиков, не как источник серверного каталога.
6. Central создаёт только root Dealer. Dealer/Subdealer создаёт только непосредственный Subdealer или Client. Родителя UI не выбирает.
7. Client не имеет management route и не управляет пользователями.
8. `active` и `price_access` наследуются сверху вниз.
9. Central получает Client redacted: без контактных/public данных и secret hint.
10. Central управляет root Dealer, Dealer/Subdealer — только своими непосредственными детьми.
11. Секретный ключ Client — **ключ активации, не авторизация**. Client обязан по ключу создать уникальные login/password; дальше входит обычными credentials.
12. Перевыпуск Client key сбрасывает его регистрацию и старые credentials.
13. Все логины глобально уникальны case-insensitive. Backend проверяет это при create/edit/activation; UI показывает live availability, но не заменяет серверную проверку.
14. Пароли хранить только через `password_hash`; изменяющие запросы защищать CSRF.
15. SPA без reload: RouterLink/RouterView, без `location.reload`/`location.href` для внутренних переходов.
16. Языки проекта: `ru`, `en`, `tr` (Русский, English, Türkçe). Переключение без reload; preference хранить в IndexedDB.
17. Central выбирает глобальную тему: `default`, `soft`, `easy`, `glossy`, `material`. Все варианты используют визуальную систему WorkDesk; Default — основной вариант. Theme хранить на сервере.
18. До определения серверной темы и готовности SPA рабочий DOM скрывать preloader — не показывать промежуточные дизайны.
19. SheetJS — единственное разрешённое CDN-исключение. Загружать в фоне после `window.onload`; Excel actions используют общий Promise.
20. UI icons только локальные SVG (`assets/icons`, `assets/css/icons.css`).
21. Создание/редактирование пользователей — modal. `More` содержит Edit/Delete; Delete подтверждается отдельной modal.
22. Enter обязателен в auth forms; парольные поля имеют локальный eye toggle без ломки геометрии.
23. Динамические Vue labels использовать через binding, не одиночные `{variable}`.
24. Каждое изменение повышает `YYYY.MM.DD.N`, синхронно обновляет `VERSION`, Markdown и cache-busting.
25. `Commit.md` — одна актуальная строка. Финальный результат всегда полный ZIP с версией в имени.
26. I18n должен хранить исходный текст узла/атрибута и всегда переводить из него, чтобы RU ↔ EN ↔ TR переключались реактивно без reload и без накопления частичных переводов.
27. Каждая пользовательская runtime-строка должна проходить EN/TR coverage test; отсутствие перевода не допускается. Native labels `Русский / English / Türkçe` не переводить.

17. Контракт каталога `futuruss-matrix` v2: не зашивать whitelist `variant`; сохранять неизвестные будущие варианты, проверять формат/структуру и поддерживать `advertisingImages`.

28. Конструктор комплектаций остаётся исходным `configurator.html` и открывается Central в отдельной именованной вкладке; повторное нажатие использует ту же вкладку. Не встраивай его в iframe. API проверяет авторизацию и CSRF.
29. Рекламное изображение управляется Vue по маршруту `#/advertising` и сохраняется через `catalog_save`. HTML-конструктор не редактирует рекламу и перед полной записью сохраняет актуальные рекламные поля сервера. После сохранения открытые SPA-вкладки обновляют каталог.
30. Фото артикулов FUTURUSS загружаются и удаляются только через защищённый API в общий серверный каталог. Не сохраняй и не подмешивай их из браузерного хранилища; API разрешает изменение только Central.
